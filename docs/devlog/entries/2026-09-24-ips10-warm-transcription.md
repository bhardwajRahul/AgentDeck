# 2026-09-24 — Optional warm local Whisper transcription

Device dictation can opt into `voice.whisperServerUrl` while retaining `transcriber: "whisper-cpp"` and the existing absolute CLI/model paths. Only an HTTP `127.0.0.1` URL ending in `/inference`, without credentials, query or fragment, is accepted. Multipart WAV requests carry the configured language, reject redirects and have a five-second deadline. Unavailable, stalled or malformed server responses fall back to the configured local CLI; a valid empty transcript remains no-speech. No server is started implicitly by application code, and Apple transcription remains the default.

On this Mac, an operator-managed launchd service `dev.agentdeck.whisper-local` keeps the existing large-v3-turbo model loaded in `/opt/homebrew/bin/whisper-server`, bound to `127.0.0.1:19121`. Its plist is under the user's `Library/LaunchAgents`, working directory and logs under `.agentdeck/whisper-local`. The explicit endpoint setting is `http://127.0.0.1:19121/inference`. Removing that optional setting returns immediately to per-request CLI operation; booting out this service releases its resident model memory. Service availability and model selection are operator-managed, not inferred from the endpoint. The personal agent/model and firmware are unchanged.

A repeated captured-audio benchmark measured CLI 1.225 / 1.258 s versus warm HTTP 0.522 / 0.482 / 0.473 s with the same large-v3-turbo model and Korean language. This is recognition-stage timing, not total response latency or an accuracy improvement; the existing recording's recognition error remained. Live compiled-module checks cover the warm path and an unavailable endpoint falling back to CLI. Unit tests cover loopback validation, redirect refusal, request deadline, multipart language, empty speech and error fallback. Build/typecheck and 4,674 tests pass (two skipped), protocol generation has no drift and token checks pass; design lint retains the pre-existing built-checkout findings.
