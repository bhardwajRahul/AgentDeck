# 2026-09-24 — Reduce personal voice agent latency

Measured the installed pipeline before changing endpointing again: recent personal runs spent 8.429 and 14.859 seconds between Gateway acceptance and final answer, followed by 0.660 and 0.517 seconds to synthesize/stage audio. The main personal conversation held about 132k tokens; recent short answers also generated reasoning tokens. This identifies the agent stage as the main measured delay, without attributing all of it to reasoning or context size.

Added optional `voice.openclawThinking` (`off` or `low`; omitted/unknown inherits normal behavior). The value travels only on personal voice `chat.send` requests as `thinking`. It does not patch session defaults, switch models or discard conversation history. The installed Gateway handler forwards this field as `thinkingLevelOverride`; its reply resolver prefers that turn override to session defaults. Disabling reasoning favors voice response speed and can reduce deliberation on complex requests; remove the setting to inherit the normal policy. Added per-run agent latency logging to distinguish future agent delays from ASR and TTS. Generated Gateway schema/Swift/Kotlin shapes include the optional field.

Validation: build and typecheck passed; 4684 tests passed, two skipped, including the explicit voice override and existing unconfigured/run-scoping tests. Protocol artifacts regenerated with the field.

Further investigation found intermittent five-second VAD subprocess failures during Metal library initialization. VAD is CPU-based, so its macOS child now receives `GGML_METAL_DEVICES=''` without changing the recognizer's environment. The 12-case regression corpus retained zero negative accepts and all seven positives, with unchanged transcripts; mixed median was 463 ms versus 427 ms without the gate. Build/typecheck and 4685 tests passed after all host changes, two skipped; token mirrors synchronized and built-checkout design lint retained 171 findings.

The user expanded authorization to OpenClaw itself. A private SQLite-consistent backup and configuration backup were made before running the official `sessions.compact` operation on the existing `agent:main:main` conversation. It reported 132555 → 12126 history tokens, retaining a semantic summary and recent context. Total model input remains larger because system instructions and tool schemas are also included. Follow-up normal-answer measurements were 5.092 / 5.537 / 6.826 seconds in the agent stage. GLM-5.3 Flash trials (8.319 / 5.516 s) did not establish an improvement and its session override was removed. `thinking=off` was rejected by GLM-5.3 and that error reply is excluded from all successful latency numbers; explicit low on the original large session took 7.686 s. The context-injection experiment showed no reduction in the recorded prompt and was also removed. Final routing remains the original personal session, original model and inherited thinking policy; the new optional separate voice route is available but disabled.

Configured only the GLM-5.3 model's active-input cap to 96000 tokens through the validated OpenClaw configuration CLI, preserving its native 1048576-token metadata. This gives automatic context maintenance a lower budget before history regrows; it is not a guarantee of a fixed summary size or latency. Configuration validation passed. No session was deleted. Recovery backup is stored privately under the user's OpenClaw backups directory, not in the repository.

An acoustic test also reproduced more than 50 seconds stuck in firmware `Sending`. The existing outer 30-second deadline did not cover the inner 90-second body loop; the HTTP header used a blocking write before that loop. Header and PCM now share nonblocking writes, partial-header accounting and length validation. Body transfer has an eight-second budget and 1.5-second inactivity budget, connect uses 1.5 seconds, response status wait two seconds, and retries are bounded by a 12-second outer deadline. Transport callbacks still run cooperatively, so these are loop budgets, not a hard real-time preemption guarantee. Failures release upload ownership and report error, allowing re-wake. The existing PSRAM utterance and 60 KiB internal reserve are retained; no heap allocation was introduced. IPS10 PlatformIO build passed.
